#### Key Points

- 2026-09-09 릴리스된 v0.29.0은 594개 커밋, 277명 기여자(신규 91명) 규모입니다. Model Runner V2가 모든 모델의 기본값이 되었고, CUDA graph 메모리 프로파일링으로 KV cache 크기를 자동 산정합니다.
- batch-sharded sampling으로 스텝당 logits 메모리 사용량을 텐서 병렬(TP) 비율의 1/TP로 줄였고, 특정 아키텍처의 decode 커널에 deterministic matmul 구성을 적용해 약 3배 성능 향상을 보고합니다.
- Hy4-preview(770B/49B-active MoE), Qwen3.8-Flash-Next 다중 양자화 포맷, Kimi K3 NVFP4 체크포인트 등 신규 모델 지원이 추가됐습니다. `--per-request-spec-decode-metrics`로 요청별 speculative decoding 수락률을 OpenAI API 응답에서 확인할 수 있습니다.
- breaking change로 deprecated 모델 아키텍처 10종이 제거됐고, FlexOlmo·Olmo3·Hunyuan은 Transformers 백엔드로 이관됐습니다. PyAV 비디오 디코더 백엔드가 삭제됐고, Model Runner V1은 deprecated 상태로 v0.32에서 제거 예정입니다.

#### Limitations

- github.com/vllm-project/vllm/releases 원문(태그 페이지 및 릴리스 목록 페이지)을 직접 열어 확인했습니다(status: read). 다만 처음 연 태그 페이지 단건 조회에서 발행 연도가 잘못 표시되는 현상이 있어, 릴리스 목록 페이지 재조회와 PyPI 기록(2026-09-09)으로 날짜를 교차 확인했습니다.
- 실제 프로덕션 워크로드에서의 처리량·비용 개선폭, 이전 버전 대비 마이그레이션 비용은 이번 자료로 확인하지 못했습니다.

#### My Take

- 기존 판단과 정면으로 배치되지는 않습니다. Trial의 "긴 context와 추론 effort를 조절하는 모델 선택 전략"과 Assess의 "open-weight 모델의 폐쇄형 frontier 모델 추격"이 실제로 굴러가려면 서빙 비용이 함께 낮아져야 하는데, KV cache 자동 산정과 decode 커널 성능 향상은 그 비용 축을 낮추는 구체적 사례입니다. `infra-cost` 축은 이번 주 내내 비어 있었는데, 벤더 발표보다 이런 서빙 엔진 릴리스가 실제 운영 비용에는 더 직접적인 영향을 줄 수 있습니다.
