### Anthropic Claude Code v2.1.305 배포 — `sandbox.allowNestedUserNamespaces`, retry watchdog의 usage limit 재확인, ToolSearch 미지원 게이트웨이 회귀 수정

#### Why It Matters

- 기본 24시간 창에 포함되는 원문 직접 확인 자료입니다. 10-20 로그가 기록한 v2.1.304에 바로 이어지는 버전으로, Adopt의 "제한된 범위의 코딩 에이전트: 테스트, diff review, 사람 승인 절차가 있는 저장소 작업" 판단과 맞닿은 샌드박스·안정성 변경이 들어 있습니다. 특히 `sandbox.allowNestedUserNamespaces`는 샌드박스 보호를 일부 우회할 수 있게 하는 옵션이라 "사람 승인 절차" 전제와 긴장 관계에 있습니다.
- v2.1.304의 ToolSearch 관련 회귀(게이트웨이에서 모든 요청이 실패하던 문제)를 바로 다음 릴리스에서 고친 사례로, 10월 내내 이어진 거의 매일 단위 안정성 조정 패턴(10-19, 10-20 로그)이 계속되고 있습니다.

#### Key Points

- `sandbox.allowNestedUserNamespaces` 추가: Linux 샌드박스 안에서 명령이 user namespace를 만들 수 있게 허용(Chromium, rootless podman 등에 필요하나, 샌드박스의 파일 보호를 우회할 수 있는 수단이 됨).
- `CLAUDE_CODE_RETRY_WATCHDOG_USAGE_LIMIT_RECHECK_MS` 추가: 무인 재시도 모드(`CLAUDE_CODE_RETRY_WATCHDOG`)가 재설정 전에 사용량 한도가 해제됐는지를 다시 확인하도록 함.
- v2.1.304 회귀 수정: Vertex·Bedrock 등에서 엔드포인트/게이트웨이가 ToolSearch를 거부할 때 모든 요청이 실패하던 문제, ToolSearch가 `--tools`에서 제외된 게이트웨이에서의 실패 — 이제 ToolSearch 없이 재시도.
- 그 외 버그 수정: `modelOverrides`의 모델명이 대소문자나 `[1m]` 태그만 다를 때 `/effort`·`/autocompact` 설정이 적용되지 않던 문제; bare repository의 새 worktree가 로컬 HEAD 대신 기본 브랜치에서 시작하지 않던 문제와 사용 안 하는 subagent worktree 정리 문제; 디스크가 가득 찼을 때 Bash 명령이 원시 `ENOSPC` 경로로만 실패하던 문제(이제 디스크 가득 찼다는 메시지로 안내); 클라우드 세션/SDK의 `setMcpServers`로 전달한 MCP 서버가 같은 이름의 로컬 설정 서버로 나중에 대체되던 문제; subagent가 fallback 모델로 전환한 뒤 Claude가 작업 결과를 원래 모델 이름으로 잘못 표시하던 문제; Workflow resume이 이미 완료된 `pipeline()`/`parallel()` agent를 journal에서 불러오지 않고 재실행하던 문제.
- 그 외: `/usage` 경고가 각각 원인을 밝히는 한 줄 수정 안내로 바뀌고 `f`로 바로 적용 가능; MCP consent 다이얼로그에서 Enter가 Accept로 잘못 처리되던 문제 개선; Code Review 재검토가 이전에 남은 blocking finding이 있는데도 LGTM으로 열리던 문제 수정.
- `github.com/anthropics/claude-code/releases`(v2.1.305=2026-10-20, 전체 변경 목록 포함) 원문을 직접 열어 확인했습니다. 같은 날짜의 `code.claude.com/docs/en/changelog`는 페이지 분량(약 107만 자) 제약으로 v2.1.305 항목 자체를 이번 실행에서 교차 확인하지 못했습니다.
