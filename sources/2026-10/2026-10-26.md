#### Why It Matters

- 기본 72시간 창에 포함되는 원문 직접 확인 자료입니다(23 Oct 23:39 공개). Adopt의 "제한된 범위의 코딩 에이전트: 테스트, diff review, 사람 승인 절차가 있는 저장소 작업" 전제와 맞닿습니다. 특히 "Cloud sessions와 Remote Control 권한을 Enterprise custom roles로 분리"한 변경은 조직 단위에서 자율 에이전트 실행 권한을 세분화하는 거버넌스 기능으로, Hold의 "감사 로그와 rollback 전략이 없는 완전 자율 업무 실행"을 경계하는 기존 판단과 직접 연결됩니다.
- 10-22(v2.1.308~309)의 "샌드박스 우회 경로를 막는" 흐름과 이어서, 이번엔 "누가 어떤 클라우드 실행 권한을 가질 수 있는가"를 역할 기반으로 통제하는 방향입니다. 또한 "Prompt is too long" 이후 압축이 base64·SVG 같은 밀도 높은 텍스트를 과도하게 남겨 다음 요청도 실패하던 문제의 수정은, Adopt의 LLM 전처리·후처리 경계 설계(`topics/llm-pipeline`)에서 말하는 "컨텍스트 예산 관리" 실패 사례의 구체 예시로 볼 수 있습니다.

#### Key Points

- Enterprise custom roles에 Claude Code cloud sessions·Remote Control 권한을 추가해 Owner가 역할별로 접근을 제어할 수 있게 함. 이 권한을 켤 때는 확인을 요구하고 해당 권한을 가진 custom role 목록을 보여줌.
- Monitor tool과 플러그인 monitor를 Bedrock·Vertex·Foundry에서도, 그리고 telemetry/nonessential traffic이 꺼져 있을 때도 사용 가능하게 함.
- 일부 게이트웨이·호환 서버가 `effort-2025-11-24` beta 값이나 대화 중간의 system message를 거부해 요청이 실패하던 문제 수정 — 이제 해당 값 없이 재시도.
- "Prompt is too long" 오류 이후 압축이 base64·SVG 등 밀도 높은 텍스트를 과도하게 남겨 다음 요청도 실패할 수 있던 문제 수정.
- `cleanupPeriodDays`를 매우 큰 값으로 설정했을 때 백그라운드 정리가 최근 붙여넣은 이미지 등 파일을 삭제하던 문제 수정.
- Linux: `/sandbox`와 샌드박스 시작 경고가 Ubuntu AppArmor의 user namespace 제한이 bubblewrap 샌드박스 시작을 막을 때 그 사실과 해제 방법을 알려주도록 개선.
