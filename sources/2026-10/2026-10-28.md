### Claude Code v2.1.312 배포 — WebFetch 차단 호스트 안내 개선, 대형 파일 덮어쓰기 방지, hooks 동시 실행 상한

- source_url: https://github.com/anthropics/claude-code/releases/tag/v2.1.312
- published: 2026-10-27
- type: release
- topics: agents
- status: read
- confidence: high

#### Why It Matters

- 기본 24시간 창에 포함되는 원문 직접 확인 자료입니다(27 Oct 20:24 공개). "클라우드 세션에서 WebFetch가 호스트를 못 찾을 때, 허용된 네트워크 도메인 밖일 수 있다는 점과 어떤 호스트를 허용해야 하는지를 Claude가 명시하도록" 개선한 변경은, 이번 실행에서 실제로 반복 관찰한 동작(여러 1차 출처 도메인이 egress 차단으로 `ENOTFOUND`를 반환하고, 그 사실을 기록에 남기는 방식)과 정확히 같은 메커니즘입니다.
- "Claude가 큰 CLAUDE.md·rules 파일·@-include 파일을 시작 부분만 보고 덮어쓰던 문제"를 "전체를 읽거나 in-place로 편집하도록" 바꾼 수정은, Adopt의 LLM 전처리·후처리 경계 설계(`topics/llm-pipeline`)에서 강조하는 "컨텍스트에 무엇을 넣는가"의 실패 사례이자, CLAUDE.md 자체처럼 저장소의 지침 문서가 에이전트에 의해 부분 읽기만으로 잘못 덮어써질 위험을 줄이는 변경이라 이 저장소의 운영과도 직접 관련됩니다.
- hooks를 세션당(서브에이전트 포함) 동시 최대 24개로, timeout을 넘겨 기다린 것도 최대 12개로 제한한 변경은 Hold의 "감사 로그와 rollback 전략이 없는 완전 자율 업무 실행" 경계와 맞닿는 실행 통제 기능입니다.

#### Key Points

- WebFetch 오류 메시지 개선: 클라우드 세션에서 호스트가 resolve되지 않으면 허용된 네트워크 도메인 밖일 수 있다는 설명과 어떤 호스트를 허용해야 하는지를 Claude가 명시하도록 변경.
- 매우 큰 CLAUDE.md, rules 파일, `@`-include 파일을 하위 디렉터리에서 시작 부분만 보고 덮어쓰던 문제 수정 — Write가 전체를 읽거나 in-place 편집을 요구하도록 바뀜.
- Bash `cd`로 git 저장소 안쪽 깊이 들어간 뒤 per-directory·`paths:` skill이 발견되지 않던 문제 수정.
- prompt·agent hooks를 세션당(서브에이전트 포함) 동시 최대 24개, 그중 이벤트 timeout보다 오래 기다린 것은 최대 12개로 제한. 1초 미만 `timeout`은 1초로 취급.
- OIDC `oidc.user_id_claim` 추가 — `sub` 대신 Microsoft Entra ID의 `oid` 같은 다른 claim으로 사용자를 식별 가능.
- Claude Code가 `claude_code.safety_event` OpenTelemetry 이벤트 전송을 중단하도록 변경(상세 사유는 changelog에 없음).
- Bedrock·Vertex·Foundry·Mantle에서 모델명을 인식하지 못할 때(커스텀 배포명, inference profile ARN 등) 더 짧은 system prompt를 쓰도록 변경 — `CLAUDE_CODE_SIMPLE_SYSTEM_PROMPT=0`으로 유지 가능.
- `github.com/anthropics/claude-code/releases/tag/v2.1.312` 원문을 직접 열어 전체 changelog(약 30개 항목, General/VS Code/Cloud sessions/Remote Control/Claude Tag/Code Review 섹션)를 확인했습니다.

### Anthropic, 신약개발 파트너십 6건의 초기 결과 공개 — Claude 보조 분자 설계·규제문서 검토·임상시험 계획 평가 (모두 preclinical)

- source_url: https://www.anthropic.com/research/early-progress-drug-development
- published: 2026-10-27
- type: report
- topics: clinical-healthcare
- status: read
- confidence: high

#### Why It Matters

- 기본 24시간 창에 포함되는 원문 직접 확인 자료입니다. Trial의 "임상/헬스케어의 비진단성 행정 업무 보조: 문서 요약, 질의 초안, 코딩/분류 보조" 판단을 뒷받침하는 사례(Enveda의 규제문서 검토·초안 작성)가 포함돼 있지만, Generate Biomedicines·Divergence Labs·BigHat의 사례는 그보다 한 걸음 나간 "분자 설계 의사결정 보조"로, 기존 Radar 어느 ring에도 정확히 대응하지 않는 유형입니다.
- Anthropic 자신이 "모두 초기 단계이고 대부분 preclinical"이라고 명시한 점은 Hold의 "prospective evaluation 없이 임상 의사결정을 자동화하는 사용"을 경계하는 기존 판단과 어긋나지 않습니다(이 사례들은 임상 의사결정이 아니라 연구실 단계 R&D입니다).

#### Key Points

- Generate Biomedicines(CAR T세포 치료제): 과학자 6명이 Claude Code로 유전자 구성요소를 표준 대비 약 70% 짧게 설계. 실험실 테스트에서 면역세포의 수용체 생산량이 약 10배 증가, 종양세포 사멸 효율과 활성 지속 시간도 개선.
- Divergence Labs(식품 알레르기): 약 한 달 동안 항체 디자인 약 35,000건을 생성해 binder 3종과 IgE를 떼어낼 수 있는 디자인 20종을 찾았고, 그중 3종이 초기 테스트에서 표준 약물보다 우수.
- BigHat Biosciences(리드 최적화): Claude를 BigHat의 실험 데이터 시스템에 연결해 항체 단편 리드 2종에 대한 변이 약 1,010건을 약 10주간 제작·테스트. 최고 변이는 결합력 10배 이상, 용해도 안정성 18°C 상승, 응집 속도 100배 이상 저하.
- Enveda(제조·규제 문서): 문서 1,061페이지를 검토해 사람이 찾은 11개 이슈를 모두 발견하고 놓친 7개를 추가로 발견. 검토 시간을 25시간 이상에서 3시간 미만으로(약 89%) 단축. 규제 문서 초안을 4시간에 작성(수작업 시 약 3개월).
- Bristol Myers Squibb: 초기 단계 임상시험 계획의 성공 가능성 평가에 Claude 활용, 2027년 확대 예정.
- Anthropic 자체 프로그램: 1인 기업 Mithril Medicine(희귀 근이영양증 치료제 개발)을 인수. Claude가 운영 대부분을 맡아 아이디어에서 유의미한 마우스 실험 결과까지 18개월 미만 소요. 결과가 유지되면 2028년 말 인간 임상시험 진입 가능성 언급.
- Anthropic은 이 작업을 확장하고 더 많은 기관과 파트너십을 맺을 계획이라고 밝혔으며, Claude Science 워크벤치·Life Sciences Verification Program·guest investigator 공개모집 등 접근성 이니셔티브를 함께 소개.

#### Limitations

- 이 결과들은 Anthropic과 파트너사가 자체 발표한 사례 연구로, 독립적인 동료 심사(peer review)나 제3자 재현 검증을 거치지 않았습니다. Anthropic 스스로도 "이르고 대부분 preclinical"이라고 명시했습니다. BMS·The Column Group 사례는 수치적 결과가 아직 없고 "평가 중/확대 예정" 수준입니다.

#### My Take

- 기존 판단과 대체로 같은 방향이지만 세분화가 필요합니다. Trial의 "비진단성 행정 업무 보조"는 Enveda 사례로 뒷받침되지만, Generate Biomedicines·BigHat·Divergence Labs는 "행정 업무"보다 "분자 설계 의사결정에 직접 개입"하는 유형이라 기존 4개 ring 중 어디에 정확히 속하는지 불분명합니다. Assess의 "clinical AI에서 환자-facing agent와 clinical decision support의 실제 outcome 개선 여부"와도 다릅니다(환자가 아니라 전임상 연구 대상). 월간 리뷰에서 "비임상 R&D 보조"를 별도 항목으로 다룰지 검토할 재료로 남깁니다.
