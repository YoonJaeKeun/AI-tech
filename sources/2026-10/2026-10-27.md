#### Why It Matters

- 기본 24시간 창에 포함되는 원문 직접 확인 자료입니다. "표준 context 세션이 200K 토큰을 넘으면 'Usage credits required for 1M context' 오류로 멈추던 문제"를 "대화를 압축하고 계속 진행"하도록 바꾼 변경은, Adopt의 LLM 전처리·후처리 경계 설계(`topics/llm-pipeline`)에서 말하는 "컨텍스트 예산 관리" 실패를 줄이는 구체 사례로, 10-26 로그에서 기록한 v2.1.310의 "압축이 과도한 텍스트를 남기던 문제" 수정과 같은 축의 연속입니다.
- `self-hosted-runner`에 `--hold-idle-file`/`--max-hold-min`을 추가해 호스트가 떠난 세션을 잡아두는 기능은, Hold의 "감사 로그와 rollback 전략이 없는 완전 자율 업무 실행" 경계와 맞닿는 운영 통제 기능입니다.

#### Key Points

- 표준 context 세션이 요청이 200K 토큰을 넘을 때 더 이상 "1M context 크레딧 필요" 오류로 멈추지 않고, 자동으로 대화를 압축한 뒤 계속 진행하도록 수정. 압축 결과에 요약이 없으면 한 번 더 요청 후 교체.
- `self-hosted-runner`에 `--hold-idle-file`, `--max-hold-min` 플래그 추가 — 호스트가 떠난 뒤 남은 프로세스를 보고하는 동안 idle 세션을 유지.
- CLAUDE.md의 매우 긴 list item 하나로 시작 시·파일 읽기/편집 후 장시간 멈추던 문제, 수천 줄 편집 시 Write/Edit가 최대 5초 멈추며 "0 lines changed"로 잘못 보고하던 문제 수정.
- `SubagentStop` 훅이 구동 중인 서브에이전트마다 분당 약 2회씩 중복 발화하던 문제를 종료 시 1회로 수정.
- 인터랙티브 터미널에서 `ultrathink`가 Opus 5.5·Sonnet 5.5·Haiku 5.5·Fable 5.1(Anthropic API 경로)에서 xhigh effort로 실행되도록 변경, 작업 중 입력하면 남은 턴에 적용.
