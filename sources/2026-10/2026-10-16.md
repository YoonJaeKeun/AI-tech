#### Key Points

- METR 직원 6명이 회사 하드웨어·사무공간과, Anthropic 자체 위험 평가팀에 준하는 내부 시스템 접근권을 받고 상주 중입니다. 고객 데이터·변호사-고객 간 특권 정보·모델 아키텍처 정보를 제외한 정보 공유가 권장되며, METR은 위험 수준·사고·관행에 대한 분석을 출판할 수 있고 Anthropic은 출판을 거부할 수 없지만 좁게 정의된 범주에서 수정(redaction)을 요구할 수 있습니다. METR은 그 수정이 정당했는지에 대한 의견을 공개할 수 있습니다.
- 평가기관 접근을 3단계로 구분: Tier 1(좁은 범위 조사, Anthropic이 접근 범위를 결정하고 출판에 승인 필요, 예: SecureBio의 화학·생물무기 챕터 리뷰), Tier 2(사전 승인 없이 출판 가능하되 특정 정보 범주 삭제 요구 가능), Tier 3(METR 사례, 직원급 접근과 Tier 2에 준하는 출판권).
- 그 외 파트너: SecureBio(Tier 1, 2026년 8월 Risk Report의 화생방 챕터 리뷰 중), Accenture·Faculty(모델 평가·red-teaming·안전장치 테스트를 포괄하는 광범위한 파트너십), Hugging Face 등과는 초기 논의 단계.
- Anthropic은 이를 은행 감독 기관이 대형 은행에 상주 조사관을 두는 방식에 비유했고, 모든 frontier AI 기업이 같은 조치를 취해야 한다고 밝혔습니다.

#### Limitations

- anthropic.com/news/an-update-on-independent-evaluators 원문을 직접 열어 확인했습니다(status: read). METR의 실제 평가 결과물(출판물)은 이 발표 시점에는 아직 없고, 접근권 부여 사실과 체계 설명만 담겨 있어 실제 운영이 선언대로 이뤄지는지는 추후 METR 측 발표로 확인해야 합니다. "직원급 접근"의 구체적 범위(어떤 내부 문서·시스템까지인지)는 Anthropic 발표만으로는 알 수 없습니다.

#### My Take

- 기존 판단과 같은 방향이면서 Watchlist에 새로 추가할 만한 신호입니다. "모델 아키텍처 정보는 공유 범위에서 기본 제외"한다는 점은 투명성에 한계가 있음을 인정하는 설계이고, "Anthropic이 출판을 거부할 수 없다"는 조건이 실제로 지켜지는지는 METR의 첫 출판물이 나와야 검증 가능합니다. 다음 월간 리뷰에서 safety-governance 축의 Watchlist 항목(METR 상주 평가, 3단계 접근 프레임워크)으로 등재를 검토할 가치가 있습니다.

- 기본 24시간 창에 포함되는 원문 직접 확인 자료입니다. 10-12 로그가 기록한 Ollama의 "decision model" 통합처럼, 로컬 추론 생태계에서 주요 변경이 계속되는 가운데 llama.cpp가 2026-10-05 v0.6.0에 이어 semantic versioning 태그(v0.7.0)를 또 이어가며, 과거 로그들이 추적해 온 build 번호(bXXXXX) 중심 릴리스와 나란히 운영되는 체계로 자리잡고 있습니다.
- CURRENT.md Trial의 "추론 effort를 조절하는 모델 선택 전략"과 Adopt의 비용 효율 판단에 닿는 로컬 서빙 성능·설정 변경입니다.

#### Key Points

- LiliCorr 추측 디코딩과 GLM5-Next용 multi-token prediction(MTP)을 추가했습니다.
- 신규 `--moe-cache-mib` 옵션: host 메모리에 있는 MoE expert를 GPU LRU 캐시에 올려 디코딩을 최대 약 2.2배 가속한다고 설명하며, 멀티 GPU에서도 동작합니다.
- 신규 모델 지원: K2 Horizon(dense·MoVA), Prism Bonsai 2 27B, EmbeddingGemma-2, 여러 decision model, MiniCPM-V 4.7, Nemotron Super 3.5 VL·Bolt, maion-coder, Mellum 변경.
- 서버: 채팅 레이어가 세션 API 중심으로 재구성되고, 포맷된 출력이 part로 분리되며, slot·prompt-cache 복원 동작이 개선됐습니다. 기본 포트가 8080에서 9931로 바뀌었고(Docker 이미지는 컨테이너 내부에서 8080 유지), Web UI에 모델을 보고·로드·언로드·다운로드하는 Models Manager가 추가됐습니다.
- 백엔드: ggml이 v0.27.0으로 갱신되며 CUDA·Vulkan·Metal·SYCL 등에 걸친 작업이 포함됐습니다.

#### Limitations

- github.com/ggml-org/llama.cpp/releases/tag/v0.7.0 원문을 직접 열어 확인했습니다(status: read). 페이지 자체에는 연도 표시가 없어, 인접 빌드(b11641~b11669, 같은 날 10-15 시각대)와 이전 로그들의 날짜 흐름으로 2026년으로 추정했습니다. "--moe-cache-mib 최대 2.2배 가속"은 릴리스 노트의 자체 주장으로, 독립적인 벤치마크 재현은 확인하지 못했습니다. v0.6.0에서 v0.7.0으로의 전환이 build 번호(bXXXXX) 체계를 완전히 대체하는지는 이번 페이지만으로 확인하지 못했습니다(같은 날 여러 bXXXXX 빌드가 계속 나오고 있어, 두 체계가 병행되는 것으로 보입니다).

#### My Take

- 기존 판단과 같은 방향입니다. MoE expert를 위한 GPU LRU 캐시는 로컬/저비용 환경에서 큰 MoE 모델을 돌릴 때의 비용·속도 트레이드오프를 구체적으로 개선하는 변경이라 Trial의 "모델 선택 전략"에 실무적으로 닿습니다. decision model 계열 신규 지원이 계속 추가되는 점은 10-12 로그에서 짚은 "decision model 개념이 로컬 런타임까지 확산"된다는 관찰과 같은 방향입니다.
