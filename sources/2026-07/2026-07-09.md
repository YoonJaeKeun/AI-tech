### Previewing GPT-5.6 Sol

- source_url: https://openai.com/index/previewing-gpt-5-6-sol/
- published: 2026-06-26
- type: product-release
- topics: models, agents, evals-benchmarks, safety-governance
- status: read
- confidence: medium

#### Why It Matters

- OpenAI의 2026년 중반 frontier 모델 방향을 보여주는 릴리스입니다.
- coding, biology, cybersecurity, subagent orchestration, stronger safeguard가 함께 강조됩니다.
- 제한 preview 상태라 일반 사용성과 실제 benchmark 재현 여부는 후속 확인이 필요합니다.

#### Key Points

- GPT-5.6 계열은 Sol, Terra, Luna로 구분됩니다.
- Sol은 flagship, Terra는 균형형, Luna는 빠르고 저렴한 모델로 소개됩니다.
- `max` reasoning effort와 `ultra` mode처럼 더 많은 추론 계산과 subagent 사용을 제품화하고 있습니다.
- Terminal-Bench, GeneBench, cyber capability 평가를 주요 근거로 제시합니다.
- 모델 capability 상승에 맞춰 cyber/biology misuse classifier, monitoring, phased release 같은 layered safeguard를 강조합니다.

#### Limitations

- preview 단계라 제3자 재현 평가와 실제 비용/latency 자료가 부족합니다.
- 정부 협의와 제한 공개가 포함되어 있어 availability가 변동될 수 있습니다.

#### My Take

- GPT-5.6 Sol은 "강한 모델"보다 "더 깊은 reasoning + subagent + safeguard"가 frontier 제품의 기본 방향이 되었음을 보여줍니다.
- coding agent와 security workflow는 가장 먼저 봐야 할 실험 영역이지만, 권한과 audit log 없이 쓰면 위험합니다.

### Google I/O 2026 Developer Keynote: Agentic Workflow

- source_url: https://developers.googleblog.com/all-the-news-from-the-google-io-2026-developer-keynote/
- published: 2026-05-19
- type: product-release
- topics: models, agents, evals-benchmarks
- status: read
- confidence: medium

#### Why It Matters

- Google이 Gemini 모델, Antigravity, AI Studio, Managed Agents, Android tooling을 하나의 agent-first 개발 흐름으로 묶고 있습니다.
- "AI가 도와주는 도구"에서 "workflow를 독립적으로 탐색하고 실행하는 agent"로 포지셔닝이 바뀌는 신호입니다.

#### Key Points

- Gemini 3.5 series와 Antigravity 업그레이드가 함께 발표되었습니다.
- Antigravity 2.0과 Antigravity CLI는 specialized subagents, terminal sandboxing, credential masking, hardened Git policies를 강조합니다.
- Gemini API의 Managed Agents는 remote sandbox와 agent harness를 API 형태로 제공하는 방향입니다.
- Android CLI, Android skills, Android Bench 등 도메인별 agent tool과 평가도 함께 제시됩니다.

#### Limitations

- 발표 자료 성격이라 실제 안정성, 비용, enterprise governance 기능은 후속 문서와 실사용 평가가 필요합니다.
- Google 생태계에 강하게 묶일 수 있어 lock-in도 검토해야 합니다.

#### My Take

- Google의 방향은 "agent를 직접 만드는 개발자"보다 "managed agent platform 위에서 workflow를 구성하는 개발자"를 겨냥합니다.
- 개인 스터디에서는 Antigravity와 Managed Agents를 agent runtime/platform 축으로 추적합니다.

### Terminal-Bench 2.0

- source_url: https://arxiv.org/abs/2601.11868
- published: 2026-01-17
- type: paper
- topics: agents, evals-benchmarks
- status: read
- confidence: high

#### Why It Matters

- Terminal-Bench는 agent가 실제 command-line 환경에서 문제를 해결하는 능력을 봅니다.
- 단순 coding benchmark보다 tool coordination, environment handling, debugging, verification 능력을 더 잘 드러냅니다.

#### Key Points

- Terminal-Bench 2.0은 실제 workflow에서 영감을 받은 terminal task 89개로 구성됩니다.
- 각 task는 고유 환경, 사람이 작성한 solution, 검증 test를 포함합니다.
- 논문은 frontier model과 agent가 이 benchmark에서 아직 충분히 안정적이지 않다고 봅니다.

#### Limitations

- terminal workflow 중심이라 GUI, clinical workflow, non-technical 업무를 직접 대표하지는 않습니다.
- agent harness, tool permission, inference budget에 따라 점수가 크게 달라질 수 있습니다.

#### My Take

- 코딩 에이전트와 DevOps agent를 볼 때 Terminal-Bench는 필수 추적 대상입니다.
- 개인 실험에서는 "명령 실행, 실패 해석, 수정, 재검증" loop를 benchmark 관점으로 기록하면 좋습니다.

### International AI Safety Report 2026

- source_url: https://internationalaisafetyreport.org/publication/international-ai-safety-report-2026
- published: 2026
- type: report
- topics: models, agents, safety-governance, evals-benchmarks
- status: read
- confidence: high

#### Why It Matters

- general-purpose AI의 capability, limitation, risk, governance gap을 넓게 정리한 안전성 기준 자료입니다.
- agent, open-weight model, evaluation gap, transparency 문제를 한 프레임 안에서 볼 수 있습니다.

#### Key Points

- general-purpose AI는 다양한 전문/과학 평가에서 강해졌지만 여전히 jagged합니다.
- capability 향상은 model size 확대뿐 아니라 post-training과 inference-time compute에서도 나옵니다.
- agent는 memory, browser, computer interface 같은 tool을 통해 더 자율적으로 행동합니다.
- open-weight 모델은 연구와 접근성을 높이지만 safeguard 제거와 release irreversibility가 큰 리스크입니다.
- 평가와 제도는 빠르게 변하는 capability를 따라가기 어렵습니다.

#### Limitations

- 안전성 보고서는 보수적 해석을 택하는 경향이 있으며, 개별 제품의 실사용 ROI는 별도 자료가 필요합니다.
- 빠르게 변하는 모델 릴리스를 모두 최신 상태로 반영하기는 어렵습니다.

#### My Take

- 이 보고서는 `safety-governance.md`의 기본 프레임으로 씁니다.
- agent를 쓸수록 "모델이 해도 되는 일"보다 "시스템이 허용하는 action"을 더 엄격히 정의해야 합니다.

### FDA AI-Enabled Medical Devices

- source_url: https://www.fda.gov/medical-devices/software-medical-device-samd/artificial-intelligence-enabled-medical-devices
- published: updated periodically
- type: regulation
- topics: clinical-healthcare, safety-governance
- status: read
- confidence: high

#### Why It Matters

- 미국에서 허가된 AI-enabled medical device landscape를 확인하는 공식 기준점입니다.
- 임상 AI와 SaMD를 볼 때 규제 기대치, transparency, safety/effectiveness review를 이해하는 데 중요합니다.

#### Key Points

- FDA의 AI-Enabled Medical Device List는 미국에서 marketing authorization을 받은 AI-enabled medical device를 식별하기 위한 자료입니다.
- 각 device는 FDA의 applicable premarket requirements를 충족했고 safety/effectiveness 관련 focused review를 거쳤다고 설명됩니다.
- 이 목록은 모든 AI medical device를 완전하게 포괄하지는 않으며, FDA가 식별한 AI 관련 용어와 문서 기반으로 구성됩니다.
- FDA는 향후 LLM과 foundation model 기반 기능을 식별하고 tag하는 방법도 탐색한다고 밝힙니다.

#### Limitations

- 목록은 포괄적 registry가 아니라 식별된 AI-enabled medical device 목록입니다.
- decision summary에는 제출 자료 대부분이 포함되지 않을 수 있습니다.
- LLM 기반 기능 태깅은 향후 개선 영역입니다.

#### My Take

- clinical/healthcare AI를 공부할 때 FDA 목록은 실제 regulated AI가 어디까지 들어왔는지 보는 기준입니다.
- EDC/임상 데이터 업무에 AI를 적용할 때도 "medical device인가, clinical decision support인가, 행정 보조인가"를 먼저 구분해야 합니다.

### State of Clinical AI Report 2026

- source_url: https://arise-ai.org/report
- published: 2026
- type: report
- topics: clinical-healthcare, evals-benchmarks, agents
- status: read
- confidence: high

#### Why It Matters

- clinical AI의 발전, evidence, workflow, patient-facing AI, 평가 과제를 한 번에 보는 기준 자료입니다.
- 일반 AI 동향을 임상/헬스케어 적용 관점으로 번역하는 데 유용합니다.

#### Key Points

- clinical AI에서도 jagged frontier가 존재합니다. controlled task에서는 강하지만 uncertainty 인식과 실제 workflow에서는 취약할 수 있습니다.
- 전통적 QA benchmark가 포화되면서 real-world task, multi-turn unstructured data, consequence-aware evaluation이 중요해집니다.
- 더 좋은 모델만으로는 부족하고, better systems와 workflow design이 필요합니다.
- human + AI 조합이 인간 단독보다 나을 수 있지만, automation bias와 deskilling을 관리해야 합니다.
- 환자-facing AI는 환자가 oversight를 해줄 것이라고 가정하면 안 됩니다.
- 2026년에는 context-specific prospective trial이 중요한 다음 단계로 제시됩니다.

#### Limitations

- 보고서 자체가 landscape synthesis라서 특정 솔루션 도입 판단에는 원 연구와 trial design을 추가로 봐야 합니다.
- 의료 시스템과 국가별 규제 차이가 크므로 한국/미국/글로벌 맥락을 구분해야 합니다.

#### My Take

- 임상 AI 스터디는 "의학 문제를 잘 맞히는 모델"보다 "안전한 업무 흐름을 만드는 시스템" 중심으로 봐야 합니다.
- EDC/clinical data 업무에서는 비진단성 workflow automation부터 작게 검증하는 편이 좋습니다.
