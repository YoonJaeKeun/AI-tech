### MCP, 파일 업로드·다운로드 실험적 확장 공개 — "Exploring File Uploads and Downloads in MCP"

- source_url: https://blog.modelcontextprotocol.io/posts/exploring-file-uploads-and-downloads-in-mcp/
- published: 2026-11-10
- type: announcement
- topics: agents
- status: read
- confidence: high

#### Why It Matters

- 확장 창(지난 7일, 발행일 2026-11-10) 자료입니다. 지금 기록하는 이유: Trial의 "원격 sandbox 또는 격리된 terminal 기반 에이전트 실행" 항목이 파일 입출력을 어떤 표준으로 처리할지와 직결되는 발표입니다.

#### Key Points

- `io.modelcontextprotocol/files` 확장(실험적, draft, 참조 구현 없음, 연내 stable 목표). 프로토콜 리비전 `2026-07-28` 이상에서 동작하며 초안 명세는 GitHub `specification/draft/file-uploads.md`에 있음.
- 설계 목표는 파일 내용이 모델을 거치지 않고 클라이언트↔도구 간에 직접 전송되도록 하는 것.
- 업로드 흐름: 서버가 도구 입력 스키마의 파일 인자에 `x-mcp-file` 표시 → 클라이언트가 먼저 메타데이터만 보내 권한·용량 확인 → 서버가 `upload_required` 응답(업로드 위치 포함) → 클라이언트가 HTTPS PUT/POST로 업로드 → 도구 호출 재시도 → 서버가 업로드를 검증한 뒤에야 도구 실행.
- 다운로드 흐름: 완료 결과의 `_meta`에 다운로드 대상 정보 포함 → 클라이언트가 HTTPS GET으로 수신.
- 전송 대상마다 `credentials` 필드를 `omit`(MCP 자격증명 미전송, 자체 인증 사용)/`include`(MCP 서버 origin에만 전송)로 구분. 리다이렉트는 거부되고 목적지 allowlist 사용을 권장.
- 확장을 지원하지 않는 클라이언트·서버는 별도 작업이 필요 없음(선택적 확장).
- 저자: Den Delimarsky(Lead Maintainer), Wil St. Charles(Google). File Uploads Working Group은 Anthropic+OpenAI가 시작했고 10월부터 다운로드도 범위에 포함.

#### Limitations

- `blog.modelcontextprotocol.io` 원문을 직접 WebFetch로 열어 확인했습니다(발행일 "Nov 10, 2026" 표기, 실험적 단계임을 원문에서 "still very much an experimental effort"로 명시한 것을 재확인). 일부 세부 수치(maxInlineBytes 등)는 2차 출처에만 나와 본문에는 포함하지 않았습니다.

#### My Take

- 기존 판단과 어긋나지 않습니다. 위 MCP 릴리스 주기 발표와 같은 흐름 — 거버넌스(릴리스 리듬)와 기능 확장(파일 I/O)이 같은 주에 나란히 나왔습니다.

#### My Take

#### My Take

- 기존 판단과 어긋납니다(2026-11-17 로그의 제외 판단을 정정). "원문을 못 열었다/비어 있었다"는 판단도 재확인이 필요할 수 있다는 사례로, 다음부터는 "빈 릴리스"로 제외하기 전에 페이지를 한 번 더 확인하는 편이 안전해 보입니다.
