#### Why It Matters

- 기본 72시간 창에 포함되는 원문 직접 확인 자료입니다(직전 기록인 v2.1.318은 2026-11-05 로그에 이미 있습니다).
- 새 권한 설정 `permissions.denyInsteadOfPrompting`은 권한 프롬프트에서 사람이 기다리는 대신 자동으로 거부하고 턴을 계속 진행시키는 옵션으로, Hold의 "감사 로그와 rollback 전략이 없는 완전 자율 업무 실행" 경계와 정면으로 맞닿습니다. 이 기능은 "프롬프트 대신 멈추지 않고 넘어간다"는 점에서 Adopt의 "제한된 범위의 코딩 에이전트(사람 승인 절차)" 판단이 전제하는 승인 절차 자체를 설정으로 끌 수 있게 하므로, 이 저장소가 이 기능을 쓸 때는 기본값을 유지해야 한다는 점을 분명히 남길 만합니다.
- 텔레메트리/feature flag가 꺼진 상태(LLM 게이트웨이 뒤 등)에서 auto mode가 더 이상 내장 분류기로 조용히 폴백하지 않고 명시적으로 묻거나 거부하도록 바뀐 것은, "운영 통제 기능 추가" 흐름에서 조용한 폴백을 없애고 실패를 드러내는 방향입니다.
- 권한 우회 보안 수정 4건(Bash 환경변수 접두사 조작, `sed` 명령의 accept-edits/auto mode 우회, worktree 생성 시 샌드박스 탈출, 인용된 단어가 포함된 Bash deny/ask 규칙 누락)은 Hold 경계의 "완전 자율 업무 실행"이 실제로는 설정된 권한 경계를 우회당할 수 있었다는 구체적 실패 모드였고, 이번 패치로 막혔다는 점에서 안정성 강화 방향입니다.

#### Key Points

- `permissions.denyInsteadOfPrompting`: 권한 프롬프트로 대기할 도구 호출을 자동 거부하고 턴을 계속 진행. 터미널 세션, subagent, teammate에 모두 적용.
- MCP 서버가 도구 호출을 task로 실행하면 Claude Code가 이를 백그라운드로 옮기고 완료 시 결과를 보고. `CLAUDE_CODE_DISABLE_MCP_TASK_BACKGROUND`로 되돌릴 수 있고, `CLAUDE_CODE_DISABLE_MCP_TASKS=1`로 MCP task 자체를 끌 수 있음.
- 텔레메트리/feature flag가 꺼진 auto mode(LLM 게이트웨이 뒤 포함)는 서버가 확인할 수 없는 호출을 내장 분류기로 폴백하지 않고 묻거나 거부. `CLAUDE_CODE_AUTO_MODE_SERVER=0`으로 기존 분류기 동작 유지 가능(Bedrock/Vertex/Foundry는 영향 없음).
- 보안 수정: Bash 권한 우회(환경변수 접두사 조작), `sed` 명령이 accept-edits/auto mode 권한 검사를 건너뛸 수 있던 문제, worktree 생성 시 샌드박스 탈출, 인용된 단어를 포함한 Bash deny/ask 규칙이 명령을 누락하던 문제.
- 동작 변경: self-paced `/loop`가 턴 종료 후 재스케줄 없이 끝나도록 변경(`CLAUDE_CODE_LOOP_KEEPALIVE=1`로 기존 동작 유지), Bash 도구가 조회 목록 밖 플래그를 쓴 `which` 실행 전 확인 요청, `--add-dir` 디렉터리는 신뢰 대화상자 수락 후에만 플러그인 마켓플레이스 등록.
- 기타: `/claude-api latency-optimize` 신설, `/usage`에 일부 게이트웨이 사용자 대상 기간별 지출 표시, `/tasks`에 완료된 subagent용 "Earlier in this session" 행 추가, Claude apps gateway에 `login_notice` 설정·JSON 로그 출력·pooled budget 우선순위 설정 추가.
- `github.com/anthropics/claude-code/releases/tag/v2.1.319`와 `code.claude.com/docs/en/changelog`의 2026-11-06("November 6, 2026") 항목 양쪽에서 같은 변경 목록을 확인했습니다.
