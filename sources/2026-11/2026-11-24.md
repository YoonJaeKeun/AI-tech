#### Key Points

- 대상 패키지: langchain-text-splitters 1.2.0, langchain-tests 1.2.0, langchain-qdrant 1.2.0, langchain-perplexity 1.5.0, langchain-ollama 1.2.0, langchain-nomic 1.1.0, langchain-huggingface 1.3.0, langchain-fireworks 1.8.0, langchain-exa 1.2.0, langchain-classic 1.1.0.
- Breaking change: EOL된 Python 3.10 지원을 전체 파트너 패키지에서 제거(#41268 / #41344).
- `langchain` 코어가 `langgraph>=1.2.16`을 요구하도록 변경(langchain-huggingface 1.3.0 릴리스노트 기준).
- 보안: `pygments>=2.20.0` 강제(CVE-2026-4539 대응), filelock/urllib3/pillow/requests 등 취약 의존성 버전 회피·패치.
- 버그 수정: `Chain.save()` 회귀 수정(#35667), `EnsembleRetriever.arank_fusion` 문자열 정규화 불일치 수정(#38051), forced tool choice·스트리밍 토큰 카운트 오류 수정(#42043).
- Core에 `reasoning_effort`를 표준 chat model 파라미터로 추가(#38887).

#### Limitations

- GitHub releases 개요 페이지와 `langchain-classic==1.1.0`, `langchain-huggingface==1.3.0`, `langchain-qdrant==1.2.0` 태그 페이지를 각각 WebFetch로 직접 열어 확인했습니다(high). 각 페이지는 커밋 제목만 나열해 세부 설명(특히 pygments CVE의 정확한 영향 범위)은 커밋 타이틀 추론에 의존했습니다. perplexity/ollama/nomic/fireworks/exa 패키지는 목록에서만 확인했고 개별 릴리스 페이지는 열어보지 않았습니다.

#### My Take

- 기존 판단과 어긋나지 않습니다. Adopt의 "LLM 전처리·후처리 경계" 판단과 직접 연결되는 통찰은 아니고 유지보수성 변경(Python 버전 EOL, CVE 패치)이 중심입니다. 코어가 아닌 파트너 패키지 10종이 한꺼번에 움직인 점만 관찰해둡니다 — `reasoning_effort` 표준화는 Trial의 "긴 context와 추론 effort를 조절하는 모델 선택 전략" 항목과 약하게 연결됩니다.
