#### Why It Matters

- 기본 24시간 창에 포함되는 원문 직접 확인 자료입니다(직전 기록인 v2.1.317은 2026-11-04 로그에 이미 있습니다).
- 클라우드 세션이 저장소를 고르지 않고 시작할 수 있는 "No repository" 옵션은 Adopt의 "제한된 범위의 코딩 에이전트" 판단과 맞물려, 코드 저장소 작업이 아닌 범용 에이전트 실행 用途가 플랫폼 차원에서 분리되고 있다는 신호입니다.
- Claude apps gateway의 `mantle` upstream에 `assume_role`을 추가해 다른 AWS 계정의 role로 동작하고 개발자별 AWS 비용 귀속을 가능하게 한 변경은, Watchlist의 비용·인프라 축에서 조직 단위를 넘어 "개발자별" 비용 가시성까지 세분화되는 흐름입니다.
- 공유 네트워크 홈 디렉터리에서 `~/.claude.json`·설정·로그인 정보가 저장 중 삭제·공백화·구버전으로 교체되는 문제를 다수 고친 것은, 다인 환경에서 에이전트 설정이 깨지는 구체적 실패 모드를 줄이는 운영 안정성 변화로, Hold의 "감사 로그와 rollback 전략이 없는 완전 자율 업무 실행" 경계와 반대 방향(안정성 강화)에 있습니다.

#### Key Points

- 클라우드 세션에 저장소를 고르지 않고 시작하는 "No repository" 옵션을 Anthropic 호스팅 환경에 추가.
- Claude apps gateway `mantle` upstream에 `assume_role` 추가(다른 AWS 계정 role 사용, 개발자별 AWS 비용 귀속).
- 공유 네트워크 홈 디렉터리에서 설정/로그인 파일이 삭제·공백화·구버전 교체되는 문제 다수 수정, 파일이 없을 때 재확인하도록 개선.

#### Why It Matters

- 기본 24시간 창에 포함되는 원문 직접 확인 자료입니다. llama.cpp는 매일 b-prefix 마이크로 빌드(b120xx대)를 계속 내고 있지만, 이번 v0.9.0은 전 버전 v0.8.0 이후의 이름 붙은(semantic) 버전 릴리스로, 그동안의 누적 변경을 하나로 묶었습니다.
- OCP FP8 E4M3 텐서 타입 지원과 ggml v0.29.0의 NCCL 기반 멀티노드 텐서 병렬화는 Watchlist의 "비용·인프라·서빙" 축에서, 로컬/자체 호스팅 추론 스택이 대형 모델을 더 적은 메모리·더 여러 노드로 돌릴 수 있게 하는 구체적 능력 확장입니다. vLLM의 CUDA 13.0 단일화(2026-11-03 기록)와 함께 보면, 서빙 스택들이 이번 주 연속으로 하드웨어 활용 범위를 넓히는 업데이트를 냈습니다.
- 신규 모델 지원 목록에 "Mistral Large 4"가 포함된 것은, 이 모델의 실제 출시 자체를 간접적으로 뒷받침하는 신호이지만 정확한 발행일은 여전히 공식 출처로 확인하지 못했습니다(아래 Limitations).

#### Key Points

- OCP FP8 E4M3 텐서 타입 지원(변환 헬퍼, 신규 ftype 포함).
- `flash_attn_ext_rows` op 추가로 멀티시퀀스 추론의 통합 KV 캐시 성능 개선, 배치 텐서 복사 API 추가.
- 신규 모델 지지: Clover-35B-A3B-Preview, Limite 1B, Metis-1.6, Mistral Large 4.
- 오디오: Chatterbox TTS, Nemotron 3.5 Transcribe, 사전정의 Pocket TTS 음성 추가.
- Gemma 4(E2B/E4B) prefill 속도 개선.
- ggml을 v0.29.0으로 갱신: NCCL 기반 멀티노드 텐서 병렬화, CPU/CUDA/SYCL/Metal/Vulkan/OpenCL/Hexagon 백엔드 작업.
- `github.com/ggml-org/llama.cpp/releases/tag/v0.9.0` 원문을 직접 열어 하이라이트를 확인했습니다. 이전 버전은 v0.8.0으로 표시되어 있었습니다.

#### Limitations

- 페이지에 연도가 표시되지 않아 "4 November, 13:08"이 2026년이라는 점은 같은 날 함께 올라온 b12xxx 빌드들의 날짜 표시와의 연속성으로 추정했습니다. v-prefix 버전 태그와 b-prefix 빌드 태그의 관계(어떤 기준으로 v 릴리스를 끊는지)는 페이지 자체에 설명이 없어 확인하지 못했습니다. "Mistral Large 4" 지원 추가가 이 모델의 공식 출시일과 같은 시점인지는 알 수 없으며, Mistral 공식 사이트는 이번에도 egress 차단으로 직접 확인하지 못했습니다(2026-11-04 로그에서 이미 "2026-10-29/2026-10-06 날짜 불일치"로 기록을 보류한 것과 같은 모델입니다).

#### My Take
